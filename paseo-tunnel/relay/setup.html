Own Paseo relay – setup

Relay address: tether-desk.duckdns.org:443 (TLS)
Works from the PC, the phone and the corporate MacBook (Zscaler), tested 2026-11-10.

Paseo connects your phone and other computers to the Paseo daemon through a relay. By default that is relay.paseo.sh. Your own relay now runs on the Hetzner server. Traffic stays end-to-end encrypted, so the relay only sees IP addresses, timing and sizes.

1. Switch a computer (each PC or Mac that runs Paseo)

Run these commands in a terminal on that computer. They change only the relay part of ~/.paseo/config.json, then restart the daemon.

Windows (PowerShell):

$p = "$env:LOCALAPPDATA\Programs\Paseo\resources\bin\paseo.cmd"
& $p daemon config set daemon.relay.endpoint       tether-desk.duckdns.org:443
& $p daemon config set daemon.relay.publicEndpoint tether-desk.duckdns.org:443
& $p daemon config set daemon.relay.useTls true
& $p daemon restart

Mac (Terminal):

p=/Applications/Paseo.app/Contents/Resources/bin/paseo
$p daemon config set daemon.relay.endpoint       tether-desk.duckdns.org:443
$p daemon config set daemon.relay.publicEndpoint tether-desk.duckdns.org:443
$p daemon config set daemon.relay.useTls true
$p daemon restart

Check that it worked: daemon pair must print a link that starts with relay://tether-desk.duckdns.org:443/ and contains ssl=true.

& $p daemon pair        # Windows
$p daemon pair          # Mac
Corporate Mac (Zscaler): Zscaler re-signs the TLS connection, so the Mac needs the CA fix from paseo-tunnel/README.md (paseo-corp-ca.sh). It is already installed, and it covers this relay as well. Without it Paseo reports unable to get local issuer certificate.

2. Pair your devices again

Phones and other computers saved the old relay address in their host entry, so pair each one again:

  • Phone: in the Paseo app, choose Add host → Scan QR code and scan the QR code from daemon pair, or the one under Settings → (this host) → Pair a device. Then remove the old entry.
  • Another computer: Settings → Add host → paste the relay://… link.

Treat the pairing link like a password: anyone who has it can control that daemon.

3. Undo (back to relay.paseo.sh)

$p daemon config unset daemon.relay.endpoint
$p daemon config unset daemon.relay.publicEndpoint
$p daemon config unset daemon.relay.useTls
$p daemon restart

(On Windows put & in front of $p.) Then pair your devices again.

Port 443Tether's Caddy forwards the path /ws to the relay, through the drop-in /etc/tether/caddy.d/paseo.caddy (3 lines; Tether's Caddyfile already imports that folder). Same certificate as Tether. Tether's own paths (/ws/id, /ws/relay, /api, …) are unchanged.
Filespaseo-tunnel/relay/ in the repo: install.sh, paseo.caddy, paseo-relay.service, test-e2e.sh, this page
ssh -i ~/.ssh/tether_hetzner tadmin@46.224.17.114
systemctl status paseo-relay                          # state
journalctl -u paseo-relay -f                          # who connects
sudo bash /etc/paseo-relay/install.sh uninstall       # remove everything

A changed or removed drop-in needs a restart of Tether's Caddy (its admin API is off): about 1 s without HTTPS, and Tether clients reconnect. install.sh does that only when the drop-in changes, and puts the old config back if Tether is not healthy afterwards.

Test from the PC (throwaway daemon, does not touch your setup): bash paseo-tunnel/relay/test-e2e.sh → ALL PASS.
